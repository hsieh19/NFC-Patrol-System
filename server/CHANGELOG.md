# Changelog

All notable changes to this project will be documented in this file.

## [0.3.1] - 2026-07-20

本版本聚焦于 **生产环境网络容错优化与实时监控体验升级**。解决了局域网 HTTP 部署环境下安全 Cookie 导致的登录阻断问题，重构了管理后台的实时监控模块以支持大数据量的过滤与分页展示，并精简了硬件巡更棒的提示音系统。

### ✨ 核心功能 (Core Features)

#### 1. 生产环境局域网 HTTP 兼容登录
- **Cookie 安全策略可配置**：在生产模式下，通过引入 `COOKIE_SECURE` 环境变量支持关闭 `Secure` 属性（默认在生产环境依旧开启，以保障 HTTPS 传输安全）。
- **解决登录阻断问题**：彻底解决内网/局域网纯 HTTP 部署时浏览器拒绝保存 Token 从而反复重定向回登录页的故障。在 `docker-compose.yml` 示例中默认设置 `COOKIE_SECURE=false` 以提供开箱即用的内网部署支持。

#### 2. 监控大屏体验优化 (分页与清屏)
- **多行数自定义分页**：
  - 后端接口 `/api/admin/records` 升级支持分页查询，并针对旧版移动端请求做了优雅兼容，避免移动端页面崩溃。
  - 前端“近日动态录入”模块添加了精美分页控制器，并支持动态切换单页数据量（`10行 / 20行 / 50行 / 100行`）。
- **翻页自动刷新暂停**：为防止后台定时拉取最新记录打断管理员阅读历史数据，自动刷新（每 10 秒刷新一次）仅在第 1 页启用，翻页后自动挂起定时器。
- **一键清屏与实时捕获**：
  - 第一页顶栏新增“🧹 清除屏幕”和“🔄 恢复显示”按钮。点击“清除屏幕”可临时隐藏当前已有的历史动态，使大屏保持清爽。
  - 在清屏状态下，若有新的设备打卡实时上传，**新记录仍会被实时捕获并展示在屏幕最上方**。

#### 3. 硬件巡更棒声学精简 (静音机制)
- **屏蔽多余噪音**：移除了巡更棒除**“刷卡感应成功 (100ms短嘀一声)”**以外的全部提示音与音效延迟（包括 WiFi 成功连接提示、热点配网模式长鸣、远程唤醒三声、离线同步成功双响、以及保存配置和切换读卡模式的重启警报声），实现非打卡业务下设备的完全静音，并缩短了重启等待延迟。

## [0.3.0] - 2026-07-17

本版本聚焦于 **ESP32-C3 智能巡更棒的深度集成与超低功耗硬件系统开发**，为传统的手机 NFC 巡更系统扩展了高可靠性的专用硬件巡更棒，并实现两端的数据对时、安全 UUID 验证、卡片模式热切换及远程配置唤醒闭环。

### ✨ 核心功能 (Core Features)

#### 1. ESP32-C3 专用巡更棒支持
- **多类型传感器适配**：支持 RC522 (IC卡 13.56MHz) 和 RDM6300 (ID卡 125KHz) 硬件，支持通过心跳随服务端参数进行 IC/ID 单模工作模式的动态切换与自适应重启。
- **双字节卡号提取清洗**：设备层内置 5 字节卡号过滤器，自动剥离首字节厂商前缀，确保只向后台上传 4 字节（8 位 HEX）标准标签ID。
- **安全 UUID 通信验证**：放弃 MAC 地址，全面采用 UUID 动态加密握手校验，只有当服务端登记的 UUID 与硬件匹配时才允许通信。
- **离线 LittleFS 大容量存储**：设计了无阻塞刷卡感应与存储队列，在断网或 AP 配置期间支持秒级读卡并将数据追加写入本地 LittleFS 缓存，联网时自动批量补传数据并销毁缓存。

#### 2. 能耗管理与远程唤醒状态机
- **调试 Web 3分钟超时自动关闭**：联网后前 3 分钟提供本地 Web 状态面板，超时无 HTTP 访问则自动注销 Web 并彻底断开 WiFi。
- **周期性唤醒与射频深度休眠**：平时关闭整个 WiFi 射频以节省电能。每隔设定周期（10-3600秒，默认60秒）自动唤醒射频、同步心跳、上传缓存，完毕后立刻重新滑入休眠。
- **下一次同步自动远程唤醒**：
  - 后台巡更棒管理列表新增 **“唤醒”** 动作。
  - 巡更棒在下一次心跳周期唤醒时，自动接收服务端下发的唤醒指令，本地拉起 Web 状态服务器，响起三声哨音，且 WiFi 状态机**自动跳过射频休眠**，保持在线 3 分钟等待管理员无线连入配置。
  - 配置完毕或 3 分钟超时后自动恢复低功耗周期休眠。

#### 3. 管理后台 UI 与功能重构
- **实时监控增加卡号列**：近日动态录入中新增“标签卡号”列。已注册点位显示对应卡号；未知点位智能从备注中解析提取并展示原始卡号，提供 `select-all` 全选样式支持一键快速复制。
- **巡检点管理去 NFC 化**：将后台所有文案中的“NFC 标签 ID”修正为“标签ID”。列表中新增 IC/ID 卡片类型徽章列，行内新增和编辑支持卡片类型下拉选择。
- **本地配置网页体验优化**：状态页面“时间对时”项引入东八区时区锁死机制（CST-8），实时格式化显示本地北京时间（解决慢 8 小时问题）。并在页面中挂载了 1.5s 周期 AJAX 状态自动刷新，杜绝手动刷新操作。

### 🛠 工程化优化 (DevOps)

- **数据库结构演进**：Prisma 模型 `Checkpoint` 新增 `cardType` 属性，`PatrolWand` 关联表新增 `shouldWakeServer` 属性。
- **接口微服务升级**：重构了点位 CSV 导入/导出，使其兼容包含卡片类型的四列读取输出。重构心跳对时接口以支持指令下发。

## [0.2.0] - 2026-03-05

本版本聚焦于 **数据库性能优化与海量数据治理**，为系统应对每年 5000 万+ 条打卡记录的工业级高频场景提供了完整的架构保障。

### ✨ 新功能 (Features)

#### 1. 数据库性能索引优化
- 为 `PatrolRecord` 添加 `[userId, createdAt]`、`[checkpointId, createdAt]`、`[status, createdAt]` 等复合索引，千万级数据查询提速百倍。
- 为 `RepairReport` 添加 `[createdAt]`、`[userId, createdAt]`、`[status, createdAt]` 索引。
- 为 `Checkpoint`、`Route`、`Plan` 添加 `groupId`、`roleCode` 索引，加速数据隔离查询。

#### 2. 冷热数据自动归档系统
- 新增 `PatrolRecordArchive` 归档表，与主表完全同构，用于存储 6 个月以前的历史打卡数据。
- 新增智能查询路由 (`record-utils.ts`)：后端根据查询时间范围自动判断从主表还是归档表获取数据，前端完全无感知。
- 新增每日静默归档引擎 (`cron-archive.ts`)：借助 Docker 健康检查的心跳机制，每 24 小时自动将超过 6 个月的打卡记录平滑迁移至归档表，确保主表始终保持轻量高效。

### 🛠 工程化优化 (DevOps)

- **Docker 零配置自动建表**：新增 `docker-entrypoint.sh` 入口脚本，容器首次启动时自动校验并推送数据库表结构（含索引），部署者无需手动执行任何数据库命令。
- **Dockerfile 完善**：Runner 阶段注入 Prisma CLI 工具包与 openssl 依赖，支持运行时 `db push`。
- **跨平台兼容**：自动消除 Windows CRLF 换行符，防止 Shell 脚本在 Linux 容器中执行报错。

## [0.1.0] - 2026-03-05

这是一个里程碑版本，标志着 **NFC 巡更点位管理系统** 的核心架构与功能集完整上线。本版本聚焦于提供企业级的 NFC 巡更闭环体验，并深度适配了内网 PWA 离线场景。

### ✨ 核心功能 (Core Features)

#### 1. 数字化巡更打卡 (Mobile App)
- **Web NFC 深度集成**：支持手机靠近 NFC 标签自动打卡，响应速度 < 500ms。
- **PWA 离线模式**：
    - 采用 **Stale-While-Revalidate** 缓存策略，支持弱网或断网环境下依然能“秒开”应用。
    - 实现了 **PWA 断网离线打开** 功能，适配内网 HTTPS 证书信任场景。
- **离线补录 (Offline Sync)**：基于 IndexedDB 的前端数据库，信号盲区自动转离线存储，恢复后手动/自动同步。
- **语音与辅助反馈**：打卡成功伴随震动反馈与沉浸式语音播报。

#### 2. 管理中枢 (Admin Dashboard)
- **RBAC 权限体系**：内置超级管理员、管理员、运维、安保四个标准角色。
- **点位与路线管理**：支持 NFC 标签物理绑定、逻辑分组及虚拟巡更路线规划。
- **计划与排班**：支持每日、每周、循环排班，确保巡更任务按序执行。
- **考核分析与审计**：
    - 后端实时聚合巡更完成率数据。
    - 支持全量历史记录追溯，并提供 **CSV 数据导出**。
- **软删除机制**：删除巡更计划时保留其关联的所有历史考核记录，确保审计完整性。

#### 3. 基础设施与安全 (Infrastructure)
- **多端识别分流**：根据设备 U-A 智能引导用户进入 Mobile 或 Admin 界面。
- **JWT 强加密鉴权**：全站基于 `jose` 库实现 Edge 级 JWT 校验。
- **系统初始化向导**：内置 `/init` 路由，支持零配置快速部署初任超级管理员。

### 🛠 工程化优化 (DevOps)

- **Next.js 16 Standalone**：大幅度精简 Docker 镜像体积。
- **GitHub Actions 矩阵构建**：单次推送自动生成 `latest` (MySQL) 及 `latest-sqlite` (SQLite) 双版本镜像。
- **内网 HTTPS 快速适配**：内置 `mkcert` 工具集成，解决内网 PWA 安装的信任锁死问题。
- **健康检查**：新增 `/api/health` 接口，支持分布式环境下的容器监控。

### 🔧 修复与调整 (Fixes)

- 修复了 Next.js 16 开发模式下频繁出现的“Negative time stamp”红屏报错。
- 修复了 `manifest.ts` 与静态文件冲突导致的 PWA 解析失败。
- 优化了 proxy 拦截逻辑，确保 PWA 核心资源（SW/Manifest）不受权限限制。
